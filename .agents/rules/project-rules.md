## 1. プロジェクト基本情報

### 1.1 基本情報

- プロジェクト名：シフトカレンダー登録アプリ
- 概要：勤務表の画像ファイルから指定スタッフ（デフォルト：皿田）の勤務予定をAIおよび画像処理で抽出し、月間カレンダー確認・手動調整のうえ Appleカレンダーへ自動登録（または `.ics` 出力）するローカルWebアプリ。
- 目的：勤務表画像からのシフト確認および Appleカレンダー登録作業の省力化・正確化。
- 解決する課題：紙や画像の勤務表から手作業でカレンダーへ転記する手間とミスの削減。
- 想定ユーザー：個人利用（ローカルMacおよび同一Wi-Fi内のiPhone利用者）。
- 主な利用環境：macOS（ローカルPythonサーバー + ブラウザ）、同一Wi-Fi内のiPhone Safari。
- プロジェクトの状態：保守・機能ブラッシュアップ中（既存稼働アプリ）。
- 現在の開発段階：UI/UX改善および精度向上の継続改善フェーズ。

### 1.2 成功条件・スコープ

- 必須の成果：勤務表画像の補正・解析、カレンダー／調整テーブル／元画像ビューワーでの確認・修正、Appleカレンダー自動登録・上書きおよび `.ics` 出力が正常に動作すること。
- 対象範囲：ローカルWebアプリ（`app.py`, `index.html`）、画像歪み補正・グリッド検出ロジック、履歴管理、起動スクリプト・macOSアプリラッパー。
- 対象外：外部クラウドへのデプロイ、マルチテナント公開運用。
- 品質・運用上の詳細目標：未確定（要ユーザー確認）。

## 2. 機能要件と仕様

### 2.1 主な機能（README.md および既存実装より確認済み）

1. **画像読み込み・歪み補正・AI解析**：勤務表画像（JPG, PNG, HEIC等）の読み込み、幾何学的歪み補正（Dewarping）・グリッド検出、Gemini APIによる対象スタッフのシフト抽出。
2. **月間カレンダー表示・勤務集計**：日曜始まり7列グリッドの月間カレンダー表示、月単位での出勤・休み・有給日数集計。
3. **シフト調整テーブル**：ドロップダウン選択によるシフト区分（早A〜遅C、日、休、有給等）の即時修正と時間・登録名の連動。
4. **元画像ビューワーと連動確認**：拡大・縮小・パン移動対応の元画像ビューワー表示、カレンダー・元画像・調整テーブル間の連動ハイライト。
5. **凡例クリックによるハイライト**：シフト区分ごとの強調表示切り替え。
6. **Appleカレンダー登録・`.ics`出力**：出勤（時間指定イベント）、休み・有給休暇（終日イベント）の登録、同日予定の重複防止・自動上書き。
7. **履歴の自動保存・閲覧・削除**：`history/*.json` への保存・復元・削除。
8. **外観モード切り替え・iPhone連携・自動終了**：システム／ライト／ダーク切替、同一Wi-Fi内iPhoneアクセス、ブラウザ終了時のバックグラウンド自動終了。

### 2.2 業務ルール（確認済み事実）

- 出勤区分定義（`config.json`）：早A（06:00〜15:00）、早B（06:30〜15:30）、早C（07:00〜16:00）、早D（08:00〜17:00）、日（08:30〜17:30）、遅A（09:00〜18:00）、遅B（09:30〜18:30）、遅C（10:00〜19:00）。
- Appleカレンダー登録名：出勤は `[区分] (HH:MM〜HH:MM)`（時間指定）、休みは `休み`（終日）、有給休暇は `有給休暇`（終日）。
- 詳細な例外処理・業務上の不変条件：未確定（要ユーザー確認）。

### 2.3 仕様の優先順位

- 既存実装・`README.md`・ユーザーの明示的な仕様指示に差異がある場合は独断で正本を書き換えず、差異を報告してユーザー判断を仰ぐ。

## 4. 技術スタックと開発環境

## 5. アーキテクチャと設計原則

### 5.1 全体構成

- `app.py`：HTTPサーバー（`RequestHandler`）、共有状態管理、自動終了監視、起動エントリポイント、および既存テスト互換のDIファサード。
- `shift_calendar/`：バックエンド機能別モジュール（`domain.py`, `image_processing.py`, `calendar_export.py`, `gemini_client.py`, `config.py`, `storage.py`）。
- `index.html`：UIレイアウト、CSS（ライト／ダーク対応、macOS HIG準拠のカプセル型デザイン・絵文字不使用）、フロントエンド状態管理・イベント連動ロジック。
- `config.json`：APIキー、デフォルトスタッフ名、カレンダー名、シフト時間定義。
- `history/`・`history_images/`：解析履歴JSON（軽量メタ＋シフト配列）および分離保存された元画像データ（`.b64`）の保存ディレクトリ（旧形式JSONの後方互換読込に対応）。
- `tests/`：画像処理・行事抽出・Geminiクライアント・履歴永続化・セキュリティ・UI連動の `unittest` スイート（12テストファイル＋`dom_harness.py`）。
- `start.sh` / `launch.command` / `シフトカレンダー.app`：起動・終了管理。

### 5.2 設計原則・変更時の保護

- 現行の軽量構成（`app.py` + `shift_calendar/`、`index.html`、外部ビルドツール不使用）を尊重し、依頼なく無関係な分割やフレームワーク導入を行わない。
- `shift_calendar/` 配下のモジュールは依存性注入（DI）を維持し、`app.py` 経由の既存テスト・起動スクリプトとの互換性を保護する。
- UIデザインは既存方針（macOS HIG準拠・カプセル型・絵文字不使用・ライト／ダーク両対応）を維持する。
